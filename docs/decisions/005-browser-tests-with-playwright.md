# 005: Browser tests with Playwright, baselines rendered in one Linux image

**Status:** accepted
**Date:** 2026-11-23

## Context

The public demo (`demo/public`) is the part of the project most people see,
and until now nothing tested it in a browser. The Python suite checks the
exported data (`tests/test_mobile_demo_data.py`) but not that the page
renders it, that the approval step works, or that a style change did not
break the layout.

## Decision

- **Playwright with TypeScript, in its own `e2e/` package.** It drives
  Chromium, Firefox and an emulated phone from one test file, has screenshot
  comparison built in, and its JSON reporter gives machine-readable failures.
  Keeping it in a separate Node package leaves the Python dependencies and CI
  untouched.
- **The page is served locally** by a 30-line Node server through
  Playwright's `webServer`. Tests never depend on the live site.
- **Baselines are rendered in `mcr.microsoft.com/playwright:v1.65.0-noble`**,
  the image the CI job runs in. Screenshots differ between operating systems
  (fonts, anti-aliasing), so baselines from a Windows laptop would fail on
  Linux CI. They are generated by a manual CI run (`update_snapshots`) and
  committed.
- **External links are not fetched.** Their hosts and exact URLs are
  asserted instead; fetching GitHub and LinkedIn from CI would be slow and
  rate-limited.

## Consequences

- Visual tests are only meaningful in that image; on other machines run
  `--ignore-snapshots`.
- Updating Playwright means regenerating the baselines in the matching image.
